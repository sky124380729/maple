切换地图时：大模型负责“理解”，本地程序负责“执行”

你的想法适合做成一次性的地图标定流程，而不是让大模型持续控制角色。

地图切换后的流程

进入新地图 / 画面稳定后
1. 截取连续几帧，确认画面已经稳定
2. 固定 UI 模块读取 HP、MP、地图名和小地图
3. YOLO 检测角色、野怪、掉落物、梯子候选区域
4. 大模型分析整张地图，提出平台/梯子/跳跃连接候选
5. 几何校验候选：平台高度、水平距离、角色可达性
6. 生成本地“地图标定文件”，供状态机执行
7. 置信度不足时暂停并请求人工确认

大模型输出的不是按键，而是地图结构

{
"map_id": "forest_01",
"platforms": [{"id":"p1","x1":20,"x2":420,"y":510}],
"ladders": [{"x":350,"y1":300,"y2":510}],
"links": [{"from":"p1","to":"p2","action":"jump_right"}],
"confidence": 0.86
}

这些坐标还要经过本地规则校验和短距离探路验证；不直接信任模型幻觉。

健康度检测建议

主通道：像素/颜色

  • 按比例化 ROI 定位 HP、MP 条。
  • 用颜色占比估算当前百分比，低延迟、可解释。
  • 连续多帧确认后才触发补血，避免动画抖动误判。

备用通道：OCR/模板

  • 读取数字或状态图标，作为颜色估计的交叉验证。
  • 两者冲突时进入保护状态并暂停输入。
  • 大模型只在 UI 改版或识别持续失败时协助重新找 ROI。

安全原则

地图标定失败、血量读取冲突、连续多帧看不到角色、窗口失焦或输入回执异常，统一进入“暂停并报警”，而不是继续猜测。

✓

采用地图标定 + 本地执行

大模型低频分析地图结构；本地几何和状态机执行移动、跳跃与战斗。
