# Maple 生产输入替换与 Windows 成品化设计

日期：2026-08-15
状态：待用户书面复核
适用范围：获得授权的测试客户端

## 1. 背景与已验证事实

现有 Maple 已具备 React/.NET 8 工作台、共享契约、视觉与地图模块、状态机、回放输入和 Windows Host 基础。原生产输入设计依赖自有虚拟 HID，但测试签名与客户端启动要求冲突，无法作为可用的发布路径。

独立 Windows 探针已完成两组实机对照：

- `keybd_event(VK, scan=0)`：系统调用和前台/完整性检查通过，但客户端未观察到位移；
- `keybd_event(VK, hardwareScanCode, EXTENDEDKEY)`：客户端产生明确位移。

成功证据会话为 `%LOCALAPPDATA%\Maple\input-probe\20260815-122248-925`。左方向使用 `VK_LEFT / scan 0x4B / down flags 0x1 / up flags 0x3`，角色从画面约 `x=318` 移到 `x=194`；右方向使用 `VK_RIGHT / scan 0x4D / down flags 0x1 / up flags 0x3`，角色回到约 `x=318`。两次动作目标窗口均保持前台，输入代理与目标均为高完整性，且 `allKeysReleased=true`。

该证据只证明左右方向键路径可用，不代表跳跃、爬梯、攻击、补药、拾取、视觉闭环或长时间稳定性已通过。

## 2. 目标与非目标

### 2.1 目标

- 用扩展扫描码 `keybd_event` 完全替换虚拟 HID 生产路径；
- 保留现有 `IInputAdapter` 抽象、Null/Replay 测试后端和反馈驱动状态机；
- 将输入能力接入正式 .NET 8 Host，而不是继续扩展独立探针；
- 完成前台运行、全局暂停/急停、动作后置视觉确认和所有停止路径 `ReleaseAll`；
- 首先在“彩虹岛·蜗牛打猎场 I”完成移动、跳台/爬梯、攻击、补药和可选拾取闭环；
- 支持导入兼容 `.mapzip` 地图包，视觉录制与百炼结构标定作为缺失或验证失败时的兜底；
- 发布无需驱动、测试签名或系统重启的 Windows x64 自包含产品。

### 2.2 非目标

- 不写入或修改游戏内存，不注入客户端，不修改网络协议；
- 不通过窗口消息把动作定向到后台客户端；
- 不实现隐藏输入来源、绕过反作弊或规避封禁的能力；
- 不允许 React 发送原始键名、VK、扫描码、按下/抬起事件或逐帧图像；
- 不将来源和许可证未确认的第三方地图资源直接打包分发。

## 3. 总体架构

用户只启动一个 `Maple.exe`。主程序保持普通权限，首次进入自动运行时拉起一个最小化的管理员输入代理 `Maple.InputBroker.exe`，用户只需确认一次 UAC。代理不显示独立工作窗口，由主程序展示连接和安全状态。

运行链路固定为：

`游戏客户区 -> Capture -> OpenCV/OCR/YOLO -> ObservationSnapshot -> SafetyGate -> ActionPolicy -> AbstractAction -> InputBroker -> 扩展扫描码 -> 新画面后置确认`

模块职责：

- `Maple.Host`：窗口绑定、前台切换、倒计时、全局热键、进程生命周期和 UI bridge；
- `Maple.Runtime/Core`：安全门、状态机、路径/动作决策、反馈驱动时长和有界时序扰动；
- `Maple.Input`：抽象输入合同、活动键注册表、输入编码与 ReleaseAll 语义；
- `Maple.InputBroker`：唯一真实键盘事件边界；
- React：配置、状态、地图、日志和遥测，只提交开始/暂停/恢复/急停等用户意图。

## 4. 管理员输入代理

### 4.1 IPC 边界

Host 与 Broker 使用当前用户专属的命名管道。Host 启动 Broker 时生成一次性会话标识和随机令牌；管道 ACL 仅允许当前登录用户，Broker 校验父进程、协议版本和会话令牌。

IPC 只接受以下白名单消息：

- `ArmTarget`：绑定 HWND、PID、进程启动时间和可执行文件身份；
- `KeyDownAction` / `KeyUpAction` / `PressAction`：只携带抽象动作、profileId、计划保持时长和动作 ID；
- `Heartbeat`；
- `ReleaseAll`；
- `Shutdown`。

Host 和 React 均不能通过 IPC 传入任意 VK、扫描码或标志。Broker 内部维护受支持键位到 VK/扫描码的固定映射，配置只选择已声明的逻辑键。

### 4.2 输入编码

- 方向键使用硬件扫描码：左 `0x4B`、右 `0x4D`、上 `0x48`、下 `0x50`；
- 方向键按下使用 `KEYEVENTF_EXTENDEDKEY`，抬起使用 `KEYEVENTF_EXTENDEDKEY | KEYEVENTF_KEYUP`；
- `Alt`、`Ctrl`、`Z` 和技能/药水键在独立实机矩阵中验证其 VK、扫描码和扩展标志，未验证的键保持不可用；
- 所有键必须显式成对按下/抬起，Broker 维护大小写无关的活动键注册表；
- 左右、上下互斥，发送相反方向前先释放旧方向；
- 单次保持时间和连续动作数量有硬上限，不能由 UI 绕过。

### 4.3 Broker 安全门与 watchdog

每次发送前，Broker 独立复核：

- 目标 HWND 仍属于已绑定 PID，进程启动时间和身份未变化；
- 目标窗口可见、未最小化且客户区有效；
- `GetForegroundWindow()` 等于目标 HWND；
- Broker 完整性不低于目标完整性；
- Host 心跳、观察帧 TTL 和动作截止时间仍有效；
- 当前会话未暂停或急停。

任一条件失败时拒绝新动作并 `ReleaseAll`。Host 断开、心跳超时、IPC 异常、Broker 未处理异常和正常退出都执行全键释放。Broker 不负责视觉或策略，不能自行循环攻击。

## 5. 用户交互

### 5.1 开始与恢复

点击“开始运行”后：

1. 检查客户端唯一匹配、画面稳定、模型/地图/配置可用；
2. 必要时请求一次 UAC 并连接 Broker；
3. 进入 3 秒倒计时；
4. 将冒险岛切到前台并再次确认；
5. 安全门通过后开始观察与动作闭环。

点击主程序窗口或切到其他应用会导致目标失焦。Host 必须立即通知 Broker `ReleaseAll` 并进入“失焦暂停”。修改设置后点击“恢复”，重新执行倒计时和前台确认。

### 5.2 全局热键

- 默认 `F9`：暂停/恢复；
- 默认 `F12`：紧急停止；
- 热键可配置，但必须检查与动作键、系统保留热键和彼此之间的冲突；
- 急停路径不依赖 React 或 WebView2 存活；
- 热键注册失败时自动运行不可启动，UI 显示失败原因。

### 5.3 UI 状态

工作台明确显示：Broker 连接/完整性、目标前台状态、当前状态机、暂停原因、当前抽象动作、实际按下时长、活动键、最后 ReleaseAll 结果、最近视觉后置确认和 `F9/F12` 热键。

## 6. 动作调度与有界随机性

动作首先由距离、角色速度、平台边界、技能冷却和最新画面反馈计算基准时长，再施加有界随机扰动。随机性用于避免固定机械节拍并增强对采样/动画差异的鲁棒性，不得替代视觉决策或突破安全门。

- 移动保持时间默认在基准值的约 `±8%` 内扰动，具体范围可按动作 profile 配置并设硬上限；
- 动作间观察窗口从受限分布采样，不使用固定循环；
- 补药、拾取和技能仍由状态触发，只对安全范围内的时序做小幅变化；
- 相同动作连续执行时插入新帧确认，不能一次生成长按键脚本；
- 会话记录随机种子、基准值、扰动值和最终时长，使失败能够确定性回放；
- 平台边缘、低 HP/MP、低置信度和急停优先级高于任何随机性。

## 7. 地图来源与生命周期

地图来源优先级为：

1. 已验证的 Maple 地图档案；
2. 用户本地导入的兼容 `.mapzip`；
3. 本地多帧视觉录制；
4. 低频百炼视觉结构标定。

兼容 `.mapzip` 是普通 ZIP，包含 `manifest.json`、`map.json` 和怪物模板 PNG。导入器解析平台、梯子、平台连接、跳跃/下落/传送连接、小地图 ROI 和模板参数，转换为 Maple `candidate`，绝不直接标为 `validated`。

首次进入导入地图时，本地视觉校准小地图缩放/偏移、分辨率和 UI 版本，并以短时实地观察验证关键连接。通过后保存为 `validated`。缺包、客户端版本不匹配、坐标校验失败或结构覆盖不足时，进入多帧录制；百炼只识别平台、梯子、边界、层级和坐标，不生成按键或路线。

当前第三方目录未发现明确开源许可证或源码仓库，因此首版只支持用户本地导入，不把其中 42 个地图包随产品分发。获得原仓库与许可证后再决定是否内置。

## 8. 当前地图导航与战斗闭环

首个完整支持地图为“彩虹岛·蜗牛打猎场 I”。实现顺序：

1. 定位角色脚底、当前平台和静态场景位移；
2. 校准左右移动速度；
3. 验证 `Alt` 跳跃、上下方向和梯子；
4. 建立平台/梯子/下落连接并完成“巡回各平台后返回起点”；
5. 接入蜗牛检测与 Player 排除；
6. 移动到攻击范围，验证 `Ctrl` 攻击后等待怪物状态变化；
7. 接入 HP/MP、补药、可选 `Z` 拾取和技能 profile；
8. 完成失焦、碰撞、角色丢失、地图变化和死亡/弹窗暂停。

跳平台使用角色脚底、目标平台边界和实测跳跃曲线决定起跳点、方向键与 `Alt` 的时序。爬梯先对齐梯子中心，再按上/下并以高度变化确认。未知边缘或未验证下落连接禁止尝试。失败时停止输入、重新定位和重规划，不盲目重复。

## 9. 云端模型与密钥

百炼调用保持低频并仅用于地图标定/低置信度复核。实时移动、战斗、补药和急停不依赖云端。

API Key 只能由用户在设置页输入，使用 Windows DPAPI 加密后存放在用户配置目录。Key 不写入源码、环境样例、日志、诊断包、截图或 Git；UI 默认遮罩，仅提供替换和清除。聊天中已经公开的密钥必须撤销，不得用于实现或测试。Endpoint 和模型白名单由产品版本控制，图片上传前继续要求用户明确同意。

## 10. 异常处理

- 失焦、最小化、客户端退出/重启、黑帧和过期帧：ReleaseAll 并暂停；
- 短暂定位丢失：停止动作，连续稳定帧达到门槛后自动恢复；
- HP/MP 冲突、未知弹窗、地图验证失败：保持暂停并显示原因；
- Broker 断开、超时或崩溃：Broker watchdog 与 Host 双侧释放，进入急停；
- 动作无预期视觉结果：重新定位和规划，不按固定次数重发；
- WebView2 刷新/崩溃、Host 关闭和未处理异常：不依赖页面执行 ReleaseAll；
- 日志记录动作依据、IPC 序号、实际编码、按下/抬起、活动键和后置观察，但不记录密钥或原始用户敏感信息。

## 11. 测试与验收

### 11.1 自动测试

- Input 编码、互斥方向、活动键、异常释放和有界随机性单元测试；
- Broker IPC schema、ACL、会话令牌、父进程/目标身份、重放和超时测试；
- Host 前台切换、倒计时、F9/F12、失焦和 WebView2 故障测试；
- Replay 闭环覆盖移动、跳跃、爬梯、攻击、补药、拾取和失败重规划；
- `.mapzip` 正常/缺字段/越界坐标/路径穿越/压缩炸弹/恶意文件名测试；
- DPAPI 往返、日志脱敏和诊断包密钥扫描；
- 保留 `node tools/verify-portable.mjs` 作为每次修改后的基础门禁。

### 11.2 Windows 实机证据

- 每个生产键分别记录前台、完整性、VK、扫描码、flags、按下/抬起和画面结果；
- 当前地图完成移动、跳跃、梯子、攻击、补药和拾取逐项证据；
- 失焦、切窗口、急停、关闭 Host、关闭 Broker、关闭游戏和客户端重启均不得卡键；
- WGC/预览记录 1280x720 与 1440x900 的 FPS、P50/P95/P99、丢帧和内存；
- OpenCV/OCR/YOLO 在当前地图数据集达到主规格门槛后才开放自动运行；
- 先完成 30 分钟运行，再完成 4 小时和 8 小时 soak；误动作和卡键必须为零。

### 11.3 完成定义

只有以下条件同时满足，首版才能称为可完整运行：

- 当前地图导航与战斗闭环实机通过；
- 输入、视觉、地图、Host 和 UI 状态一致；
- 所有故障路径 ReleaseAll 通过；
- Windows 发布包无需虚拟 HID、测试签名和重启；
- 自动测试、Windows 实机证据和稳定性测试均保存到版本化验证文档。

## 12. 迁移与交付顺序

1. 更新唯一主规格和 Windows 交接，正式批准生产输入变更；
