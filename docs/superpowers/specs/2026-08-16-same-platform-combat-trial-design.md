# 同平台自动战斗试运行与预览整理设计

日期：2026-08-16
状态：用户已确认设计，等待书面规格复核

## 1. 目标

在不要求完整地图拓扑的前提下，提供一次由用户明确启动、最长 15 秒的同平台自动战斗试运行，用于验证真实客户端上的 `视觉识别 -> 目标选择 -> 短距离移动 -> Broker 输入 -> 新画面反馈` 闭环。同时修复原生预览错位并降低画面内遥测噪声，让识别框和游戏画面成为中央区域的主要内容。

本设计是 `docs/MAPLE_PROJECT_SPEC.md` 的实现细化。生产自动运行仍遵守完整地图、观察新鲜度、前台、Broker 和动作后置条件安全门。

## 2. 非目标

- 不实现梯子、绳索、跳跃或跨平台导航。
- 不在试运行中执行拾取、HP/MP 补给或技能循环。
- 不允许 React 发送原始键、VK、扫描码或输入报告。
- 不把单帧低分检测直接当成可行动 Self。
- 不加入反检测、隐藏进程或修改客户端内存。

## 3. UI 与预览

### 3.1 原生预览几何

React 继续只上报中央预览孔径的 CSS 像素矩形和 `devicePixelRatio`。Host 以浏览器客户区为唯一原点，将 CSS 像素转换为物理像素，并在窗口移动、尺寸变化、DPI 变化和 WebView2 内容重置时重新计算原生 `PreviewSurface` 边界。

原生画面按客户区宽高比使用 `contain` 绘制并居中，允许必要的窄幅留黑，不裁掉 HUD，不将画面固定到孔径左上角。原生预览可用时，React 空状态不得透出或与画面重叠。

### 3.2 画面信息密度

中央画面只保留：

- Self、Player、Monster 动态识别框和短标签；
- 右上角单行轻量遥测：`采集 FPS · 识别 FPS · 端到端延迟`；
- 必要的暂停或输入异常单行告警。

采集后端、模型/provider、内存、队列、丢帧、检测耗时、地图版本、HP/MP 和输入状态留在左右侧栏或日志，不再覆盖游戏内容。画面遥测使用低对比半透明底，仅占单行，不形成多层卡片。

设计读法：这是桌面运营工作台，沿用现有 Ant Design 和深色冷灰色令牌；`DESIGN_VARIANCE=3`、`MOTION_INTENSITY=2`、`VISUAL_DENSITY=7`。重点是稳定、扫描效率和画面可读性，不引入营销页构图或新组件体系。

## 4. 识别与角色确认

显示阈值与动作阈值分离：新鲜且达到低显示阈值的检测均可绘制，显示分数不因动作门禁被隐藏。动作侧不直接忽略置信度，而是将连续三帧的唯一性、位置一致性、框尺度和受控水平位移融合成 Self 身份置信度。

同平台试运行前，程序执行一次不超过 180ms 的受控水平移动并观察新帧。只有一个候选轨迹按预期方向移动且场景/镜头补偿后位移成立时，才确认 Self。多候选同时移动、方向相反、无位移或帧过期均拒绝试运行。

Monster 必须连续三帧存在、类别和位置轨迹一致。目标限定为 Self 脚底高度带内、水平距离最近且未越过当前可见平台边界的 Monster。Player 永不进入目标选择。

## 5. 同平台战斗试运行

### 5.1 入口和生命周期

用户在停止或暂停态点击“同平台试运行”。Host 启动生产 Broker，显示 3 秒倒计时并将目标客户端切为前台。所有前置条件通过后创建 `CombatTrial` 受监督会话上下文；公共状态机继续使用现有 `Navigating`、`Attacking` 和 `Paused`，不新增跨协议状态。最长 15 秒后自动结束并暂停。

试运行不是可恢复的长期自动会话。任何中断都结束本次试运行，用户必须重新点击入口并重新完成前置检查。

### 5.2 动作闭环

1. 从最新观察中选择同平台最近 Monster。
2. 目标超出攻击距离时，只规划一次 80-250ms 的 `MoveLeft` 或 `MoveRight`。
3. Broker 在 key-down 前和保持期间复核绑定目标仍为系统前台；Host 持续采集新帧。
4. Self 进入攻击距离、接近本地平台边界、目标消失或位移反馈异常时立即 key-up。
5. 进入攻击距离后执行一次 `Attack(profileId=singleAttack)`，默认逻辑键为 `Ctrl`；保持时间受 60-120ms 档案边界约束，当前默认 80ms，并由最新动画/攻击反馈决定是否提前结束。
6. 等待新画面，依据目标位置、数量或攻击反馈决定再次攻击、重新靠近或结束。
7. 连续两次攻击无可解释反馈时结束并暂停。

动作间隔由新鲜画面、几何关系和反馈决定，不使用固定循环周期。首版不为规避检测添加伪随机行为。

### 5.3 立即停止条件

以下任一条件触发 `ReleaseAll` 并结束试运行：窗口失焦或身份变化、帧过期、黑帧、Self/Monster 丢失、多个 Self 候选、平台边界不明、输入 Broker/IPC/心跳异常、动作超时、用户 F9、F12、窗口关闭或未处理异常。当前可见平台边界必须由角色脚底附近的连续支撑表面检测得到；无法得到左右安全边界时不允许试运行。

## 6. 协议边界

React 只提交 `combat.trial.start` 和现有暂停/急停意图。Host 生成 `AbstractAction`，再通过 `BrokerActionExecutor` 和 `Maple.InputBroker.exe` 执行。React 不接收逐帧图像，不提交动作序列，也不提供按键持续时间。

Host 发布试运行状态、当前阶段、选中目标、最近抽象动作、剩余时间和结束原因。所有结果写入现有 JSONL 诊断流。

## 7. 测试与验收

### 7.1 自动测试

- 预览孔径在 1440x900、1280x720、100/125/150% DPI 下与原生 Surface 对齐，尺寸变化不积累偏移。
- 中央画面不存在旧四行遥测面板，只有单行精简遥测。
- 低显示分检测仍能绘制，过期检测仍按 TTL 隐藏。
- Self 受控移动确认覆盖正确方向、反方向、无位移和多候选。
- 试运行只产生左右移动和单体攻击；任何其他动作被拒绝。
- 所有完成、取消和异常路径都调用 `ReleaseAll`。
- React 命令继续拒绝 raw key、VK、scanCode、flags 和报告字节。

### 7.2 用户监督实机验收

自动测试和发布通过后，用户接受 Broker UAC 并保持角色位于有怪物的开阔平台。依次验收原生预览对齐、Self/Monster 框、左右靠近、`Ctrl` 攻击、视觉反馈提前释放、15 秒自动停止、F9 和 F12。没有这组证据时不得标记 Windows 自动战斗 PASS。

## 8. 错误处理

所有错误均转为中文可诊断原因，不静默失败。预览几何异常只隐藏原生 Surface 并暂停，不发送输入。识别不足保留画面和低分框供诊断，但不自动降级到盲目巡逻。Broker 无法启动、UAC 被拒绝或前台确认失败时不发送任何动作，并显示原生错误码。
