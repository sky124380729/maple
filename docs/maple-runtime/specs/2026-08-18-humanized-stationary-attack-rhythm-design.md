# 定点压键攻击随机节奏设计

日期：2026-08-18

状态：已确认设计，等待实施计划

## 1. 目标

强化定点攻击，使角色不再以固定节拍持续攻击，而是模拟人工持续压住攻击键、短暂左右调整位置并偶尔休息的节奏。随机性必须有明确安全边界、可记录、可回放、可测试，且不能绕过现有观察、安全门和虚拟 HID 输入链路。

本功能不尝试通过纯图色识别“实际攻击了多少次”。一次攻击阶段只统计持续压住攻击键的时间，不把按键重复、动画次数或命中次数作为结束条件。

## 2. 已确认行为

一个完整节奏周期按以下顺序运行：

```text
AttackHolding -> RepositionFirst -> RepositionGap -> RepositionSecond -> OptionalRest -> AttackHolding
```

### 2.1 持续压住攻击键

- 每轮只发送一次攻击 `key-down`，到本轮结束时发送一次对应的 `key-up`；不得在轮内模拟连续点击或重复 key-down。
- 计划保持时间按整数毫秒抽样，范围为 1–30 秒，并使用分段权重：
  - 88%：`[20_000, 30_000]ms`；
  - 9%：`[10_000, 20_000)ms`；
  - 3%：`[1_000, 10_000)ms`。
- 三段权重总和必须为 100。每轮独立抽样，不做“避免连续相近数值”的人为修正。
- 倒计时到零后释放攻击键并进入移动；任何安全条件失败时必须提前释放，不能等待计划时长结束。
- 普通短按攻击档案仍可保留原有 `minHoldMs/maxHoldMs`；定点压键节奏使用独立的最长 30 秒攻击限制。移动、跳跃、拾取、补给等动作不得继承该长时限制。

### 2.2 随机左右移动

- 首方向在安全允许时按 50%/50% 抽取 `Left` 或 `Right`，第二段必须使用相反方向，因此每轮可能是左→右，也可能是右→左。
- 两段移动保持时间分别独立抽取 `[60, 400]ms`，不得复制第一段时长作为第二段时长。
- 两段移动之间的无按键间隔独立抽取 `[50, 350]ms`。
- 平台边界、视觉反馈或安全门可以缩短、拒绝或改变随机移动；安全约束优先于统计分布。被调整的原始抽样值和最终执行值都要写入日志。
- 两段时长不要求相等，因此移动结束后可以产生轻微净位移；下一轮仍由最新观察重新确认安全状态。

### 2.3 偶发休息

- 完成两段移动后，独立进行一次休息判定：25% 概率进入休息，75% 概率直接开始下一轮攻击。
- 休息时长均匀抽取 `[2_000, 5_000]ms`。
- 休息是运行时内部的无输入阶段，不使用会终止当前会话的 `Pause` 抽象动作。
- 休息期间必须确认没有活动按键，并继续处理停止、失焦、EmergencyStop、设备异常和帧新鲜度检查。

## 3. 运行时设计

新增边界明确的节奏控制器，由它管理当前周期、阶段、已抽取时长和阶段截止时间。它只输出阶段意图，实际按键仍必须经过现有策略、安全门、动作执行器和虚拟 HID 适配器。

为保证可测试性，随机源和单调时钟必须通过接口注入：

- 生产环境使用进程级真实伪随机源和单调时钟；
- 测试环境使用脚本化随机序列和可控时钟；
- 不允许在 React 中生成随机数，也不允许 React 发送方向、按键或保持时间。

攻击阶段不能继续依赖固定“最多反馈帧数”来决定何时释放。运行时必须以单调截止时间为主，同时持续消费最新观察。每次观察都重新执行安全门；截止时间到达或安全失败时立即执行 key-up。停止、取消、异常和宿主退出的 `finally` 路径仍必须执行 `ReleaseAll`。

阶段转换只在前一阶段的按键已确认释放后发生。不得预先生成整段动作脚本；进入新阶段时才抽取该阶段所需的随机值，以保留实时反馈能力。

## 4. 契约与配置

`Attack` 仍使用已有的 `profileId=singleAttack|areaAttack`，不新增原始按键动作类型。动作契约按动作类型分别限制持续时间：

- 定点压键 `Attack`：计划保持时间最大 30,000ms；
- 其他主动动作：继续使用现有短时安全上限；
- `holdMs` 不得大于对应动作的 `maxDurationMs`。

默认配置增加 `combat.stationaryRhythm`：

```json
{
  "enabled": true,
  "attackHoldBands": [
    { "minMs": 20000, "maxMs": 30000, "maxInclusive": true, "weight": 88 },
    { "minMs": 10000, "maxMs": 20000, "maxInclusive": false, "weight": 9 },
    { "minMs": 1000, "maxMs": 10000, "maxInclusive": false, "weight": 3 }
  ],
  "reposition": {
    "minHoldMs": 60,
    "maxHoldMs": 400,
    "minGapMs": 50,
    "maxGapMs": 350
  },
  "rest": {
    "probability": 0.25,
    "minMs": 2000,
    "maxMs": 5000
  }
}
```

首版使用上述验收值，不要求在 UI 中开放概率和范围编辑。配置仍需经过范围、权重总和和最小值不大于最大值校验。

## 5. 页面倒计时

工作台增加“随机节奏”状态卡，由 Host 发布 `combat.rhythm.updated` 事件驱动。事件至少包含：

- `cycleId`；
- `phase`：`idle|attackHolding|moveLeft|moveRight|movementGap|resting`；
- `sampledDurationMs`；
- `remainingMs`；
- `updatedAtMonoMs`；
- `earlyReleaseReason`（仅提前结束时存在）。

Host 在阶段切换时立即发布，并在活动阶段约每 250ms 更新一次剩余时间。React 只负责显示，不根据倒计时发起动作。

状态卡显示当前阶段、本阶段抽中的总时长和大号剩余倒计时。例如：

- `攻击键按住中 · 本轮 26.43 秒 · 剩余 18.62 秒`；
- `右移 · 本次 0.31 秒`；
- `动作间隔 · 剩余 0.14 秒`；
- `休息中 · 本次 3.80 秒 · 剩余 2.15 秒`。

停止、会话暂停或 EmergencyStop 后显示对应状态，不继续显示一个正在递减的旧倒计时。新会话或安全恢复后必须创建新周期并重新抽样。

## 6. 日志与回放

每个周期记录周期编号、权重分段选择、原始随机数、计划时长、实际时长、首方向、两段移动时长、移动间隔、休息判定、休息时长、所有提前释放原因和安全门结果。

回放使用已记录的阶段和时长，不重新抽样；回放输入适配器仍禁止真实输入。日志不得记录原始 HID 报告或绕过现有脱敏规则。

## 7. 测试与验收

- 证明三个攻击时长分段只能生成各自边界内的整数毫秒值，并验证 88/9/3 的分段选择映射；统计测试只作为补充，不以不稳定的大样本概率断言代替确定性边界测试。
- 证明一轮攻击只有一个 key-down 和一个 key-up，计划保持期间不存在重复攻击按键事件。
- 证明倒计时到零、取消、失焦、陈旧帧、安全门失败、执行器异常和 EmergencyStop 都会释放攻击键并最终执行 `ReleaseAll`。
- 证明移动首方向可为左右任一方向、第二段方向相反、两段时长独立且均在 60–400ms，间隔在 50–350ms。
- 证明休息判定为独立 25% 分支，休息时长在 2–5 秒，且休息期间没有活动按键。
- 证明 Host 事件契约拒绝未知字段和非法范围，React 能展示攻击、移动、间隔、休息、暂停和停止状态。
- 运行项目要求的 `node tools/verify-portable.mjs`。真实 HID 行为仍需在 Windows 上运行 `tests/windows/hid_contract.tests.ps1 -RequireEvidence`，macOS 结果不能宣称 Windows PASS。

## 8. 非目标

- 不识别或统计游戏画面中的实际攻击次数、命中次数或动画次数；
- 不使用预生成的长动作脚本；
- 不允许 React 生成随机动作或发送原始按键；
- 不因“更像人工”而削弱焦点、窗口身份、帧新鲜度、地图、输入设备或 EmergencyStop 门禁；
- 不在首版开放任意概率编辑器或自定义随机分布。
