# 冒险岛怀旧服视觉自动化架构设计

## 1. 目标与边界

本项目用于在获得授权的测试环境中验证冒险岛怀旧服客户端的视觉自动化流程。程序主路径使用视觉检测和模拟输入，并允许增加只读内存观测作为可选辅助通道。程序只允许使用：

- 游戏窗口截图或屏幕截图；
- OpenCV、OCR 和目标检测进行画面识别；
- NVIDIA GPU 上的 CUDA/TensorRT 推理；
- Windows 正常的模拟键盘、鼠标输入。

只读内存的用途仅限于诊断、性能对照或在用户明确启用后提供非控制性的辅助观测；所有会改变角色、物品、资源或客户端流程的能力都不在范围内。视觉结果和安全状态优先于任何只读内存结果。

明确不做以下事情：

- 不修改或注入游戏进程内存；只读内存适配器必须独立、可关闭、可审计，不能写入客户端；
- 不拦截、修改或伪造游戏网络协议；
- 不实现反检测、绕过限制或隐藏自动化行为；
- 不向非前台游戏窗口发送不可靠的后台按键消息。

第一阶段目标是单张地图的循环打怪，并覆盖自动捡取、技能循环、HP/MP 阈值保护、异常暂停和手动停止。

## 2. 已确认的产品行为

控制台参考“左侧参数与状态、右侧实时画面”的工作台布局：

- 左侧显示运行/暂停状态、HP/MP、保护阈值、技能和捡取开关；
- 右侧显示最新截图、识别框、角色位置、目标位置和当前状态；
- 底部记录识别置信度、动作日志、截图帧率、CPU/GPU 推理耗时和异常原因。

程序运行时采用“游戏失焦立即暂停”策略：

1. 每次发送输入前检查游戏窗口是否仍是前台窗口，并确认窗口句柄未变化。
2. 游戏失焦时立即停止输入调度、清空未执行动作、释放所有可能按下的按键。
3. 程序不抢回焦点，因此用户可以安全使用微信或其他程序。
4. 切回游戏后等待画面稳定，重新确认角色和地图状态；第一阶段要求用户手动点击“恢复”。
5. 提供全局紧急停止快捷键，例如 `Ctrl+Alt+F12`，并在停止时执行按键释放兜底。

这意味着同一桌面上运行其他游戏时，冒险岛脚本不会继续操作；如果需要冒险岛持续运行并同时操作另一款游戏，应使用第二台电脑或虚拟机隔离，而不是依赖后台窗口按键。

## 3. 总体架构

```text
游戏窗口
   |
   v
截图采集器（CPU） ----> 原始帧缓冲/录像
   |
   +--> 固定 UI 感知（CPU）
   |      ROI、颜色占比、模板匹配、OCR
   |      HP、MP、技能状态、地图名、小地图指纹
   |
   +--> 动态场景感知（GPU）
   |      YOLO + CUDA/TensorRT
   |      角色、野怪、掉落物、梯子/传送点候选
   |
   +--> 地图/事件检测（CPU）
          画面稳定性、地图指纹、换频道/切图候选
                  |
                  v
        感知融合与置信度管理（CPU）
                  |
                  +--> 本地地图缓存命中：加载标定
                  +--> 新地图/低置信度：调用大模型网关
                  v
          有限状态机与安全策略（CPU）
                  |
                  v
          输入调度器（CPU）
                  |
                  v
     Windows 模拟键盘/鼠标 -> 游戏前台窗口
```

CPU 负责截图、固定 UI、OCR、跟踪、状态机、输入安全和日志；GPU 只负责 YOLO 动态目标推理。两条路径通过带时间戳的感知快照汇合，避免 YOLO 阻塞健康度保护。

## 4. 感知模块

### 4.1 游戏窗口与截图采集

采集器只服务于已选定的游戏窗口，输出带时间戳、窗口客户区尺寸和 DPI 信息的帧。所有 ROI 使用客户区相对比例保存，不写死绝对像素；首次运行或分辨率变化时执行窗口边界和 UI ROI 校准。

采集器必须支持：

- 稳定帧判定，避免切图/切频道动画期间分析；
- 可选帧率上限，默认控制在 CPU 能稳定处理的范围；
- 原始帧、裁剪帧和识别结果的录制/回放；
- 丢帧统计和截图失败报警。

### 4.2 固定 UI 感知

HP、MP、技能栏、地图名和小地图属于相对稳定的 UI，不使用 YOLO 作为主通道：

- HP/MP：比例化 ROI + 颜色占比估算；
- 数字或状态文字：OCR/模板作为备用通道；
- 技能冷却：模板、灰度/颜色状态和冷却遮罩；
- 地图名：OCR 优先，模板或区域指纹作为辅助；
- 小地图：裁剪后提取低分辨率指纹，用于已知地图匹配。

所有健康度读数都要求连续多帧一致才触发动作。颜色估计和 OCR 冲突时进入保护状态，不由大模型实时决定是否补血。

### 4.3 动态场景感知

YOLO 使用自有客户端画面采集数据进行微调，初始类别为：`player`、`monster`、`loot`、`ladder`、`portal`；NPC 等类别按实际需求追加。推理部署优先使用 NVIDIA CUDA/TensorRT，默认 FP16，模型输出必须带类别置信度和时间戳。

YOLO 负责检测，不直接决定按键。目标跟踪、最近目标选择、平台关系和动作可达性由 CPU 几何规则处理。

## 5. 地图标定与大模型网关

大模型是低频的地图顾问，不在每帧控制循环中运行。其输出必须是结构化 JSON，内容为平台、梯子、传送点及平台连接候选，不允许直接返回按键序列。

### 5.1 地图身份

地图身份由“地图名 + 小地图指纹 + 场景结构指纹”组成。程序先用本地证据判断是否命中 `map_id`：

- 命中已知地图：直接加载缓存标定，不调用大模型；
- 证据显示新地图：等待 3-5 帧稳定后调用一次大模型；
- 证据冲突或持续低置信度：暂停输入，最多触发一次复核；仍失败则等待人工处理。

### 5.2 地图标定结果

每张地图保存版本化标定文件，例如：

```text
maps/<map_id>/calibration.json
maps/<map_id>/calibration-candidate.json
maps/<map_id>/validation-log.json
```

标定结果需要通过 JSON schema、平台连续性、梯子连接、跳跃距离和短距离实地验证。候选版本验证成功后才替换当前版本，并保留旧版本用于回滚。

### 5.3 大模型调用触发条件

正常战斗和已知地图切换调用次数为 0。以下事件才允许调用：

- 首次遇到新地图；
- 角色、平台或梯子连续多帧低置信度；
- 地图名、小地图和场景结构互相冲突；
- 用户在控制台主动请求重新标定；
- 客户端分辨率或 UI 配置版本变化。

单次请求发送压缩后的地图区域和必要上下文；设置超时、重试上限和本地缓存，避免 token 不受控增长。大模型不可用时，程序保持暂停或使用已验证的旧标定，不猜测继续运行。

## 6. 换频道处理

当前频道不作为必需感知目标，用户换频道前手动停止程序。程序仍需防御意外的频道切换或切换动画：

1. 通过黑屏/淡出、画面结构突变、地图名和小地图证据变化检测“环境重置候选”。
2. 立即暂停输入并等待稳定帧。
3. 重新获取角色位置、当前平台、目标和掉落物；清空旧目标、攻击计时器和路径进度。
4. 若地图身份仍命中缓存，复用地图标定，仅恢复当前观测；不调用大模型。
5. 若地图身份不匹配或持续冲突，进入待确认状态，最多调用一次大模型做地图复核。

换频道不能直接覆盖地图缓存，也不能在切换动画中执行移动、攻击或捡取。

## 7. 决策与输入安全

有限状态机至少包含：待机、搜索野怪、接近目标、攻击、捡取、补给、地图标定、暂停、异常和紧急停止。状态转换必须带进入条件、超时和退出动作。

输入调度器是唯一允许发送键鼠事件的模块：

        - 每次动作前检查前台窗口句柄、进程标识和窗口客户区状态；
- 失焦、窗口关闭、截图失效、健康度冲突或感知超时立即进入暂停；
- 清空动作队列并释放按键；
- 不自动抢回焦点，不向后台窗口发送不可靠消息；
- 输入动作设置最大持续时间、节流和可审计日志。

## 8. 动作节奏与拟人化表现

程序不使用“固定每 N 毫秒按一次键”的主循环。动作由状态、目标几何关系、技能冷却、画面变化和上一动作结果共同驱动：

- 移动、攻击、捡取和跳跃都使用事件触发，并设置动作持续时间的合理范围；
- 输入节奏在不影响安全的前提下加入小幅、受约束的变化，但不得用于规避检测或隐藏自动化；
- 长按动作根据角色位置变化、动画/命中反馈或超时条件提前结束；
- 连续无效动作触发重新感知、短暂等待或暂停，而不是盲目重复；
- 技能循环根据冷却和战斗状态调度，不按固定时间表强行施放；
- 随机性必须可复现（记录随机种子），便于回放和调试。

所谓“拟人”只表示基于上下文的自然动作节奏和对反馈的响应，不包含反检测、规避封禁或模拟真人身份的功能。

## 9. 可观测性与故障处理

每个感知快照记录：时间戳、帧号、ROI 版本、HP/MP 读数及置信度、YOLO 推理耗时和目标列表、地图身份证据、FSM 状态、拟执行动作及暂停原因。支持“截图回放模式”，在不发送输入的情况下重现决策。

以下条件统一暂停并报警：

- HP/MP 连续读取失败或双通道冲突；
- 连续多帧看不到角色；
- 目标或平台置信度低于阈值；
- 地图标定校验失败；
- 游戏窗口失焦；
- 输入释放失败或动作超时；
- 大模型超时、返回格式错误或复核失败。

## 10. 测试验收标准

实现前先准备脱敏的实际客户端截图和录屏样本，覆盖：不同分辨率、切图动画、换频道动画、怪物密集、掉落物遮挡、技能特效、HP/MP 变化、窗口失焦和重新聚焦。

验收分四层：

1. 固定 UI：HP/MP 和地图名读数在样本集上稳定，异常时能暂停。
2. 动态目标：角色、野怪和掉落物检测达到约定精度，低置信度不触发危险动作。
3. 地图标定：新地图能生成可校验的候选文件，已知地图不重复调用大模型。
4. 输入安全：切到微信或其他程序后不产生任何模拟输入；返回游戏需重新确认后才恢复。

## 11. 分阶段交付

第一阶段：截图录制/回放、窗口检测、固定 UI 识别、失焦暂停和控制台日志，不发送真实输入。

第二阶段：采集并标注实际画面，训练 YOLO，加入目标跟踪和地图缓存。

第三阶段：实现有限状态机和“动作预览”模式，验证每个动作的安全条件。

第四阶段：在授权测试环境启用模拟键鼠输入，加入补给、捡取、技能循环和异常停机。

第五阶段：接入低频大模型网关，用于新地图标定、异常复核和 ROI 重新定位；任何候选更新都必须人工可见、可回滚。
