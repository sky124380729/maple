# 冒险岛测试自动化项目完整交接规格

日期：2026-08-13

状态：产品方案确认；标准输入兼容性探测完成；等待后续实现方评估 HID 输入阶段

目标平台：Windows 10/11 x64，单个窗口化客户端

适用前提：获得授权的测试环境

## 1. 产品愿景与范围

本项目是一个面向窗口化冒险岛测试客户端的桌面自动化控制台。用户期望的完整产品不是路线录制器，而是以实时画面理解当前场景、自动完成跨层移动和战斗的工具。

完整产品需要覆盖：

- 绑定一个指定的游戏窗口，提供实时画面、状态和运行控制；
- 识别角色、怪物、平台、梯子/绳索、地图边界及 HP/MP UI；
- 基于地图拓扑执行平台行走、跳跃、爬梯/绳索和边缘下落的跨层移动；
- 根据同屏目标数量，在单体攻击、自动选择和群攻优先三种模式中调度技能；
- 按百分比或最低数值阈值使用 HP/MP 药水；
- 在失焦、识别失败、卡住、补给失败或其他异常时立即暂停并保留诊断记录；
- 支持 Windows 10/11 x64 的可分发 `.exe`，用户不需要安装 Python、CUDA 或开发环境。

不在范围内：客户端内存读写、网络协议修改、客户端注入、后台窗口消息、反检测或规避安全机制。现阶段也不做多窗口/多账号管理、传送门、弹簧装置或职业专用位移技能。

产品最初采用“先验证输入兼容性，再开发视觉与策略闭环”的两阶段交付。标准输入验证已完成，其结论见第 5 节。

## 2. 已确认的产品需求

### 2.1 运行与界面

- 单个指定的窗口化游戏客户端。
- 运行主界面采用紧凑的暗色控制台：左侧显示运行状态、HP/MP、功能开关、补给阈值和停止按钮；右侧以实时游戏画面为主；高级配置放入二级页面。
- 日常运行页面只显示必须的信息，避免把地图分析、模型参数、日志回放等配置堆进主视图。地图档案、动作设置、云端增强和运行回放作为二级页面。
- 用户仅配置单体攻击键、群攻键、HP 药水键、MP 药水键、冷却/施放时长和补给阈值；方向键与跳跃按游戏固定默认键位处理。
- 攻击模式支持“单体优先 / 自动 / 群攻优先”。自动模式按同屏怪物数量阈值决定技能类型，并需设置最短切换间隔和冷却限制。
- HP/MP 补给同时支持百分比阈值和最低数值阈值。游戏 UI 分辨率可变，定位必须基于窗口客户区比例和视觉锚点，不要求用户框选。
- 运行时游戏窗口失焦、最小化、关闭、尺寸变化或视觉置信度不足时，必须暂停动作并执行按键释放。

### 2.2 地图档案与非录制式跨层导航

用户不希望逐条录制角色路线，也不以解包客户端获得地图资料作为产品前提。每张地图应保存独立的地图档案，包含：

- 平台的相对位置、有效水平范围和高度层；
- 梯子/绳索的位置及其可连接的平台；
- 可安全下落的边缘、不可通行边界和巡逻区域；
- 当前地图的身份线索，例如地图名、缩略图/场景结构指纹和窗口比例；
- 由系统推导并经用户确认的跨层连接与路径建议。

运行期将角色和怪物的实时位置投影到已确认的地图拓扑上，策略层才决定横移、上爬、下落、跳跃或攻击。任何地图结构或角色定位连续低置信度时，必须停止而不是盲目执行。

### 2.3 本地视觉与云端模型增强

- 高频运行闭环以本地视觉和规则为主，不将大模型置于每帧控制链路中。原因是实时性、稳定性、网络依赖和 token 成本均不可接受。
- 本地推荐采用 OpenCV 处理窗口/HUD/血蓝条等固定元素，YOLO 的 ONNX 模型处理角色、怪物、平台和梯子等动态元素。
- 地图配置阶段可选接入阿里云百炼视觉模型。UI 仅允许用户填写 API Key、选择预设模型；服务地址固定，不暴露通用网关配置。
- 未配置 API Key 时，本地功能仍可运行；云端增强入口应明确显示不可用，不阻塞已存在地图档案的使用。
- 云端能力可在以下低频、可审阅场景使用：首次从地图截图或短录屏帧生成平台/梯子/边界/跨层路径建议；本地视觉持续低置信度时请求复核；用户主动要求重建地图档案；客户端分辨率或 UI 外观版本变化后辅助重新定位 UI 和场景结构。
- 云端模型输出必须是结构化候选配置，不能直接返回按键序列。候选结果必须可审阅、可编辑、可版本化保存，且只有通过本地校验和用户确认后才能用于运行。
- 正常战斗、移动和补给不调用云端模型；调用失败、超时或未配置时，系统保留在安全暂停或使用已验证的本地档案，不猜测继续运行。

### 2.4 可观测性与安全控制

- 运行界面显示当前地图档案、识别置信度、角色所在层、目标数量、当前动作和最近的安全检查结果。
- 每个感知与动作事件至少记录时间戳、窗口状态、截图帧号、HP/MP 读数及置信度、目标检测结果、地图身份、状态机状态、拟执行动作、实际发送结果与暂停原因。
- 支持截图/帧序列回放，在不产生真实输入的前提下重现视觉与策略决策。
- 提供明显的启动、暂停、恢复和紧急停止控制；停止路径必须清空未执行动作，并由输入层释放所有可能处于按下状态的键。

## 3. 标准输入兼容性验证结论

### 3.1 已完成的测试

现有测试器位于 `src/MapleInputProbe/`，使用 `user32.dll!SendInput` 向已成为前台的目标窗口发送按键。已测试两条 Windows 标准输入路径：

- `KEYEVENTF_SCANCODE` 扫描码输入；
- 虚拟键码输入。

测试器在发送前检查目标窗口存在、可见、未最小化和前台状态，并在发送后显式发送 key-up；日志记录了 `SendInput` 的返回值和系统错误码。

### 3.2 当前结论

根据 `dist/input-test.log` 的记录，扫描码和虚拟键码调用多次返回成功，例如：

```text
mode=scancode key=Left ... down=1 downError=0 up=1 upError=0
mode=virtual-key key=Left ... down=1 downError=0 up=1 upError=0
```

日志同时记录目标窗口已成为前台。用户在客户端中观察到：即使系统层调用成功，游戏客户端不响应这些输入。因此，当前结论是：

> 标准 `SendInput` 不满足该目标客户端的输入兼容性要求。

这不是窗口未聚焦、扫描码/虚拟键码选错或 key-up 遗漏导致的结论。`SendInput` 探针不应再被作为完整产品的最终输入方案。

## 4. 后续输入能力要求

后续实现需要采用能向 Windows 提供键盘 HID 报告的输入路径，即虚拟 HID 键盘方案；不能仅依赖 `SendInput`。这是基于现有测试的产品前提，而不是尚待验证的假设。

本规格不规定具体驱动、库或产品实现，也不包含 Interception、驱动通信协议、安装流程、签名流程、设备枚举方式、键盘报告格式或任何规避客户端限制的技术细节。这些内容应由具备 Windows 驱动和合规审查能力的后续实现方独立评估。

后续实现方需要至少满足以下工程条件：

- 输入路径应以明确的键盘 HID 设备语义向操作系统呈现，而不是调用 `SendInput`。
- 按键状态必须可追踪，始终保证 key-down 与 key-up 成对。
- 出现异常、失焦、停止、进程退出或设备通信失败时，必须触发全量按键释放。
- 必须有独立的输入诊断页面，在接入视觉自动化前验证单键输入的可观察响应。
- 安装、权限、签名、兼容性、卸载和失败恢复必须可审计；不得让程序在无提示的情况下安装或加载系统级组件。
- 输入实现应被封装为独立适配器，和视觉、策略、UI、配置存储解耦。

### 4.1 动作调度节奏

输入调度不得采用“每隔固定 N 毫秒重复按键”的主循环。动作时间应由当前状态和画面反馈共同决定，包括目标距离、角色位移、攻击/移动动画、技能冷却、药水触发条件和上一个动作是否生效。

允许在合理范围内使用受约束的时间抖动，以避免与动画帧边界发生固定冲突；该抖动必须有上下限、可关闭、可记录，并以固定随机种子支持回放。该机制仅用于动作稳定性、动画同步和故障复现，不得用于隐藏自动化、规避检测或降低封禁概率。

每个动作都必须定义：

- 最短保持时间和最大保持时间；
- 结束条件，例如位置变化、命中反馈、动画结束或超时；
- 与同类动作的最小间隔；
- 超时、无反馈和输入失败时的暂停/释放策略。

移动键、攻击键和药水键均必须采用成对的 key-down/key-up 生命周期管理；状态切换、失焦、异常和退出时执行 `ReleaseAll`。

## 5. 建议模块边界

```text
Desktop UI
  ├─ Window binding and runtime controls
  ├─ Profiles and action settings
  └─ Logs and diagnostics

Vision pipeline
  ├─ Window capture
  ├─ HUD / OCR detection
  ├─ Object detection
  └─ Map topology and confidence fusion

Decision engine
  ├─ Cross-platform navigation state machine
  ├─ Target selection
  ├─ Attack mode selector
  └─ HP / MP protection

Input adapter
  ├─ Compatibility diagnostic
  ├─ KeyDown / KeyUp / Press / ReleaseAll
  ├─ Active-key registry
  └─ Focus and emergency-stop guard
```

输入适配器是唯一可产生键盘事件的模块。视觉与决策层仅输出抽象动作，如 `MoveLeft`、`MoveRight`、`Jump`、`SingleAttack`、`AreaAttack`、`UseHpPotion`、`UseMpPotion`。

## 6. 后续交付顺序

1. 选择并验证 HID 输入方案：只实现独立单键测试器，复用现有日志与前台安全检查，验证客户端是否有可观察响应。
2. 确认输入方案稳定后，构建完整桌面控制台与输入适配器接口。
3. 建立截图录制和离线回放，先完成 HUD、角色、怪物、平台和梯子识别，不发真实输入。
4. 建立地图档案格式、平台拓扑校验和本地跨层状态机，先使用“动作预览”模式。
5. 接入低频百炼视觉增强，用于新地图的候选档案生成、低置信度复核和主动重校准；候选必须经用户确认。
6. 在授权测试环境中接通输入适配器，逐项启用移动、攻击、补给和异常停止。

## 7. 验收要求

### 输入验证阶段

- 能绑定单个窗口化目标客户端。
- 能记录每次按键的请求、实际发送结果、前台状态和用户的客户端响应确认。
- 在用户观察下，至少验证左、右、跳跃及一个自定义技能键的客户端响应。
- 停止、失焦、窗口关闭或异常退出后没有残留按键状态。

### 完整产品阶段

- 单地图内可稳定识别角色、怪物、平台和梯子，并展示置信度。
- HP/MP 百分比与最低数值阈值均可触发对应药水动作。
- 跨层移动只在地图档案和视觉置信度满足安全条件时执行。
- 任何识别失败、位置长时间不变、窗口状态异常或补给失败均暂停并保留可回放日志。
- 云端模型未配置或调用失败时，运行时核心功能不依赖网络且不会继续猜测执行。
- 云端模型在允许的低频场景中可以被调用，其输出始终以候选地图档案或复核意见的形式呈现，不能绕过本地验证直接驱动动作。

## 9. 用户工作流

### 9.1 首次配置

1. 启动程序并从可见窗口中绑定唯一的游戏客户端。
2. 创建或选择地图档案。
3. 选择客户端窗口尺寸，运行本地 UI 锚点校准；校准以客户区比例保存，不保存绝对屏幕坐标。
4. 可选提交一张截图或短录屏帧给百炼视觉增强，生成平台、梯子/绳索、边界和跨层路径候选。
5. 在地图预览中确认或修正候选结构，执行本地拓扑校验并保存为已验证版本。
6. 配置单体攻击、群攻、HP 药、MP 药键，以及冷却、施放时长、百分比阈值和最低数值阈值。
7. 运行输入诊断，逐个验证方向、跳跃、攻击和药水键的客户端响应。

### 9.2 日常运行

1. 选择已经验证的地图档案和动作配置。
2. 确认客户端窗口可见、未最小化且为前台窗口。
3. 点击启动并通过短倒计时；倒计时后进入本地感知循环。
4. 主界面显示角色/目标/楼层、HP/MP、当前动作、攻击模式和安全状态。
5. 用户可随时暂停、恢复或紧急停止；恢复前重新执行窗口和视觉健康检查。

### 9.3 异常处理

任何安全条件失败都进入 `Paused` 或 `EmergencyStop`，不自动猜测恢复。用户可查看异常截图、事件时间线和最后一帧感知快照；修复原因后手动恢复。

## 10. 配置与数据模型

配置分为全局设置、地图档案和动作档案三类，均采用版本化 JSON。示意结构如下：

```json
{
  "schemaVersion": 1,
  "window": { "titlePattern": "冒险岛怀旧服", "clientAreaAspect": 1.7778 },
  "actions": {
    "singleAttack": { "key": "J", "cooldownMs": 800, "holdMs": 100 },
    "areaAttack": { "key": "A", "cooldownMs": 1500, "holdMs": 100 },
    "hpPotion": { "key": "1", "percentBelow": 50, "valueBelow": null },
    "mpPotion": { "key": "2", "percentBelow": 30, "valueBelow": null }
  },
  "combat": { "mode": "auto", "areaTargetCount": 3, "switchCooldownMs": 1200 },
  "map": { "mapId": "forest-east", "calibrationVersion": 1 }
}
```

敏感配置（百炼 API Key）不得写入上述档案、日志或导出报告，应使用 Windows 系统凭据存储；导出报告必须脱敏。

## 11. 运行状态与数据流

本地运行循环以带时间戳的 `ObservationSnapshot` 为边界。每一帧先采集窗口和固定 UI，再合并动态检测与地图拓扑，最后由状态机输出一个抽象动作；输入适配器在发送前重新检查安全条件。

核心状态至少包括：`Stopped`、`Starting`、`Observing`、`Navigating`、`Attacking`、`UsingPotion`、`Recalibrating`、`Paused`、`EmergencyStop`。所有状态转换必须记录原因，并有超时和退出动作。

云端调用是异步的配置任务，不得阻塞健康度监控。调用期间输入保持暂停；响应必须通过 schema 校验、拓扑校验和用户确认后才会产生新地图版本。

## 12. 性能与稳定性目标

- 窗口采集与固定 UI 检测目标频率：不低于 15 FPS（普通 CPU）。
- 动态目标检测目标延迟：本地 CPU 模式单帧不超过 250 ms；GPU 模式单帧不超过 100 ms。超时不得阻塞补给和安全暂停。
- 运行时内存目标：无 GPU 时不超过 1 GB；GPU 模式按模型实际显存需求显示诊断信息。
- 任何单次动作必须有最大持续时间；默认不允许无限长按。
- 连续识别失败、角色无位移或输入无反馈达到配置次数后自动暂停，并保存前后截图。
- 运行时默认不需要网络；只有用户主动触发配置期增强或低置信度复核时才发起云端请求。

## 13. 模型与地图版本管理

- YOLO 模型、类别清单、输入尺寸和推理后端写入模型 manifest，并随日志记录版本。
- 地图档案采用候选、已验证、已归档三态；新候选不得覆盖当前已验证版本。
- UI 锚点、地图拓扑和模型版本变化时，运行前必须重新执行一致性检查。
- 任何模型或地图档案回滚都应能通过版本号恢复，并保留失败原因。

## 14. 测试计划

### 自动化测试

- 配置 schema 和默认值校验；百分比/数值阈值互斥与边界校验。
- 地图拓扑连接、平台排序、梯子可达性和候选版本回滚。
- 状态机转换、动作超时、攻击模式切换、药水优先级和暂停恢复。
- 输入适配器的 key-down/key-up 配对、ReleaseAll、失焦阻断和设备断连处理。
- 百炼响应 schema 校验、超时、重试上限、脱敏日志和离线降级。

### 离线视觉回放

建立覆盖不同窗口尺寸、DPI、特效遮挡、怪物密集、切图动画、HP/MP 变化、失焦和重新聚焦的截图/录屏样本集。回放模式默认禁止真实输入，只验证观察结果、状态转换和暂停原因。

### 授权客户端验收

先运行独立输入诊断，再在动作预览模式确认视觉和策略；最后按移动、攻击、补给、跨层、异常停机的顺序逐项启用。每次验收记录客户端版本、窗口尺寸、模型版本、地图档案版本和测试报告。

## 15. 发布与运维

- 发布包目标为 Windows x64 自包含 `.exe`，模型和默认资源随包提供；首次启动检查资源完整性。
- 若输入适配器需要系统组件，安装器必须显式展示权限、版本、卸载和失败恢复信息，并提供诊断命令，不得静默加载。
- 日志按运行会话分目录，支持滚动保留和一键打包；截图可配置是否保存，默认对外导出时脱敏。
- 生产运行前必须显示客户端版本、地图档案版本、模型版本和输入适配器状态，任何一项不匹配都应阻止启动。

## 16. 未决事项

- 后续实现方需要在授权测试环境中独立评估并选择符合组织安全与签名要求的 HID 输入适配器。
- 需要收集首批真实截图/录屏并确定 YOLO 初始类别与目标精度门槛。
- 需要确定百炼预设视觉模型名称、单次请求最大图片尺寸和本地缓存保留周期。
- 需要在 Windows 10 与 Windows 11、不同 DPI 缩放下完成窗口采集和 UI 锚点兼容性矩阵。
